# Responsible AI Usage Policy for Software Developers

## 1. Purpose

This policy defines how developers may use AI tools (such as ChatGPT, GitHub Copilot, Claude, and similar) during software development. The goal is to harness AI's productivity benefits while protecting security, privacy, and code quality.

## 2. Data Privacy and Confidentiality

AI tools process and may retain the input they receive. Developers must never paste the following into any AI tool:

- Private company information, including internal architecture, trade secrets, or unreleased product plans
- Client or customer data of any kind
- Personal or sensitive information (names, addresses, phone numbers, government IDs)
- Internal URLs, server hostnames, or IP addresses
- Proprietary code from third parties under NDA

When discussing code, replace sensitive details with generic placeholders before submitting to an AI tool.

## 3. Secrets and Credentials

The following must never be entered into an AI tool, even in masked or partial form:

- Passwords and passphrases
- API keys and service account tokens
- Authentication tokens, session keys, and refresh tokens
- Database connection strings containing credentials
- Private keys (SSH, GPG, TLS, etc.)
- OAuth client secrets
- The contents of `.env` files or similar configuration files containing secrets
- Any credential that grants access to a production or staging system

## 4. AI Output Verification

Every piece of code produced by an AI tool must be manually reviewed before it enters the codebase. The review must check for:

- **Correctness**: Does the code actually solve the problem? Are the logic and math right?
- **Security**: Could this introduce an injection vulnerability, data leak, or privilege escalation?
- **Performance**: Is the algorithm reasonable, or does it have hidden O(n²) behavior?
- **Edge cases**: What happens with empty input, null values, boundary conditions, or concurrent access?
- **Dependencies**: Are any suggested packages real, maintained, and appropriately licensed?
- **Hallucinations**: AI tools often invent function names, library APIs, or package names that do not exist.

AI-generated code must pass the same code review, linting, and testing gates as human-written code. No shortcut is permitted.

## 5. Blind Copying

Developers must never copy code from an AI tool into a production codebase without understanding what it does. Blind copying creates several risks:

- Importing security vulnerabilities that bypass human review
- Introducing subtle bugs that pass initial tests but fail under edge conditions
- Committing code the developer cannot explain or maintain

A simple rule applies: **Do not paste code you could not write yourself from memory after reading it.**

## 6. Responsible AI Disclosure

AI usage should be disclosed honestly in the following contexts:

- **Code review comments**: When an AI tool generated the majority of a function, note it in the pull request description (e.g., "Initial implementation generated by Copilot, then manually modified").
- **Project documentation**: If AI tools were used to generate documentation, acknowledge this in the document or repository README.
- **Client deliverables**: If the client contract requires disclosure of AI tool usage, comply fully and do not omit relevant details.

Disclosure is not an admission of low quality. It is a transparency practice that builds trust.

## 7. Developer Responsibility

The developer who submits code is always the responsible party, regardless of whether a human or an AI tool wrote it. This means:

- You are accountable for bugs introduced by AI-generated code
- You must understand every line you commit
- You must ensure the code complies with company standards, licensing, and regulatory requirements
- You must not use AI to bypass security reviews, compliance checks, or testing requirements
- You must reject AI output that feels wrong, even if it looks plausible

AI tools are assistants, not authors. The signature at the bottom of the commit is yours.

## 8. Summary

| Area | Rule |
|---|---|
| Secrets | Never paste passwords, API keys, tokens, or `.env` files into any AI tool |
| Private data | Never paste client data, personal information, or internal architecture |
| AI output | Review every line for correctness, security, performance, and edge cases |
| Blind copying | Never use code you do not fully understand |
| Disclosure | Be honest about AI tool usage in PRs and documentation |
| Responsibility | The developer owns the code, not the AI tool |
